<Note>
**Phase 16** of the DealMarket Cameroon build roadmap. This breaks [Development Roadmap](/product/development-roadmap) Milestones 0–4 (Foundation through MVP Launch, weeks 1–23) into 2-week sprints with concrete backlog items. Wave 2 and Wave 3 (Milestones 5–6) are **intentionally not pre-broken into sprints here** — re-planning near-term work close to when it starts, with real MVP-phase velocity data in hand, produces a far more accurate breakdown than speculative planning today would.
</Note>

## 1. Cadence & Conventions

- **Sprint length**: 2 weeks. **Ceremonies**: sprint planning, daily standup, sprint review/demo, retrospective — standard, not elaborated further here.
- **Story format**: `As a <persona>, I want <capability>, so that <benefit>` with acceptance criteria that cite the specific FR-ID(s) it satisfies — every story traces back to Phase 2, not to ad hoc scope.
- **Definition of Ready**: a story enters a sprint only once its FR is defined, its screen exists in Phase 13/14, and its API contract exists in Phase 9 (or is explicitly scoped as part of the story).
- **Definition of Done** (sprint-level, distinct from the milestone-level exit criteria in Development Roadmap §6): code merged via CI-passing PR, unit/integration tests written, reviewed against the Component Library (Phase 14) where UI is involved, and demoed in sprint review.
- **Squads**: Platform/Backend, AI/ML, Mobile, Web, Design, QA/DevOps — per Development Roadmap §4. Sprints below note which squad(s) own each block of work.

## 2. Sprints 1–2 — Milestone 0: Foundation

<Tabs>
  <Tab title="Sprint 1 (Weeks 1-2)">
    **Goal**: Repo, environments, and core schema exist; nothing user-facing yet.

    - _(Platform)_ Scaffold the monorepo per Folder Architecture: `apps/`, `supabase/`, `packages/`, CI workflow skeletons
    - _(Platform)_ Provision three Supabase projects (dev/staging/prod); wire Deployment Architecture's Cloudflare/Vercel topology
    - _(Platform)_ Migrations: core tenancy + catalog domains (`retailers`, `branches`, `staff_members`, `products`, `promotions`, `flyers`) per Database Schema §2–3
    - _(AI/ML)_ Begin OCR de-risking: collect real flyer samples from 3–5 prospective pilot retailers, run initial extraction quality baseline
    - _(Platform)_ Begin MTN MoMo + Orange Money sandbox/compliance process (external lead time — started earliest deliberately)
    - _(Design)_ Design tokens v1 in `packages/design-tokens`: color, type, spacing, radius (Component Library §2–4)
  </Tab>
  <Tab title="Sprint 2 (Weeks 3-4)">
    **Goal**: A staff member can authenticate and the base component sets exist in both apps.

    - _(Platform)_ Migrations: consumer + monetization + marketing/AI domains (Database Schema §4–6); RLS policies migration (§6 pattern)
    - _(Platform)_ Auth: OTP flow, staff invite/accept flow, custom-claims token hook (Authentication Strategy §3–4, §7)
    - _(Platform)_ Cross-tenant RLS test suite scaffolded in `supabase/tests` (early, not deferred to hardening — NFR-SEC-008)
    - _(Mobile)_ Base widget set: Button, TextField, Card shell, BottomNavBar, app shell/router/DI wiring
    - _(Web)_ Base shadcn/ui-restyled component set: Button, Input, Card, SidebarNavItem, app shell/middleware wiring
    - **Exit**: Development Roadmap Milestone 0 DoD met
  </Tab>
</Tabs>

## 3. Sprint 3 — Milestone 1: Walking Skeleton

**Goal**: Prove the full stack end-to-end with the narrowest possible slice (Weeks 5–6).

- _(Web)_ Retailer registration → Platform Admin approval → manual promotion create (single branch, single product, no OCR yet)
- _(Platform)_ `POST /v1/promotions/{id}/publish` Edge Function live
- _(Mobile)_ Home feed renders published promotions, unranked, unstyled — proves the read path
- _(QA/DevOps)_ First full CI/CD round-trip to staging for all three pipelines
- _(AI/ML, Platform)_ De-risking tracks continue in parallel, not blocking this sprint's goal
- **Exit**: Development Roadmap Milestone 1 DoD met — a promotion is visibly flowing retailer portal → database → consumer app in staging
